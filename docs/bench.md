# bench：口径定死的那一份

迭代期间这份文件不改。改了，之前所有 run 的数就不能比了。

    python3 tools/bench.py data/runs/*/judge.jsonl        # 体检 + 三粒度 + 逐判据
    python3 tools/bench.py --closed ...                   # 不打补丁，看封闭世界下界

## 一、数据与 GT

| | |
|---|---|
| 数据 | `data/in/shane-fx-0908`，94 轮 |
| GT | `data/labels/复核-shane-fx-0908-产品.xlsx` + `data/labels/gt-补丁.jsonl` |
| 正例 | 218 条（复核表原始 155），9 格存疑两边都不计 |
| 归一 | `review.ALIAS` 把 `neg_2_3`/`neg_2_4` 并到 `neg_2_2` |

**为什么要补丁。**复核表只列出生成它那一轮命中的判据，人没机会对没列出的判据表态。
94 轮 × 14 条 = 1316 个格子，有人工意见的只有 207 个。封闭世界把剩下 1100 多个
一律当「不该命中」—— 那是假设，不是数据。`gt-补丁.jsonl` 补的就是这些格子，
每条都带 `依据`（知识库原文、权威口径、或人自己在备注/漏判说明里写过但没勾成判据的那句话）
和 `来源`。拿不准的标「存疑」，两边都不计，不往任何一边凑。

现在 78 条：

| 批次 | 正例 | 反例 | 存疑 |
|---|---:|---:|---:|
| 首批（无 `裁定方` 字段） | 16 | 3 | 3 |
| `裁定方: 机器复核` | 48 | 2 | 6 |

**机器复核那批是自己裁自己，有循环论证的风险**，所以单独打了 `裁定方` 字段，
随时能按它筛出来复审或整批撤掉。48 条正例里最硬的是人自己在漏判说明里把正确答案
逐字写出来的（净收益公式、仓位合并条件、净充值≥500U 领体验金、事件合约两条路径）；
最软的是 `neg_2_1` 那 11 条 —— 「用户要的那件事没被处理」这个尺度放得比较宽。

## 二、四个粒度，一起看

| 粒度 | 问的是 | 当前 `787213ce` 实测 |
|---|---|---|
| **判据**（主口径） | 记到哪一条上了 | P93.7 R89.0 F1 91.3 |
| 判据·开放 | 同上，但人没被问到的命中不算 FP | P93.7 R89.0 F1 91.3 |
| 主题 | 属于哪一类问题 | P94.3 R90.2 F1 92.2 |
| 整轮 | 这一轮到底有没有问题 | P97.4 R96.2 F1 96.8 |

封闭（主口径）是下界，开放是上界，真值在中间。**四个一起报，不许只报一个。**
每个粒度都要给精确率和召回率，不能只给 F1 —— 同一个 F1 可以来自「判得少但准」
和「判得多但一堆误报」，这两种对评测系统的意义相反。

上表封闭和开放两行一样，是因为当前这轮的新FP 已经全部裁完了。**新一轮 run 判出了
没人核过的格子，两行就会重新分开** —— 分得越开，主口径测的就越是 GT 的缺口而不是
judge 本身，这时先用 `tools/newfp.py` 把新FP 裁掉，再拿主口径做取舍。

## 三、run 什么时候不算数

体检先跑，再看指标。

- 单个 run：没判完的轮次（`complete=false` 或有 `groups_failed`）超过 **15%** → 作废。
  v13 掉了 19 次连接、21/94 轮没判完，它的 F1 64.9 不是判得差，是没判。
- 多个 run 比：只在**参比各方都判完整的轮次**上比（公共子集），掉线的轮次一起剔除。
  整个 run 作废太粗 —— 端点一直在抖，那样大部分 run 都得扔。
- 每个配置 **3 采样 2/3 表决**才算数。同配置单跑三遍 F1 摆 6.2 分
  （76.3 / 70.1 / 72.8），单跑只能定方向，**赢面小于 6 分不作数**。

## 四、每个 run 必须能溯源

报告抬头两条指纹，缺一不可：

- **端点指纹** `model@system_fingerprint` —— 服务端是不是同一个
- **判据指纹** `rubric.fingerprint()` —— 判据文本是不是同一版，只哈希真正进 prompt
  的字段（`desc`/`applies_when`/`right_looks_like`/`type_options`），权重和统计口径
  改了不算换版本

v8 到 v14 那几轮就是因为没记判据指纹，现在已经对不上各自用的哪版判据文本。

## 五、迭代怎么走

    执行  python3 cli.py run data/in/shane-fx-0908 --samples 3 --vote-k 2 -o data/runs/<名字>
    统计  python3 tools/bench.py data/runs/<名字>/judge.jsonl data/runs/<基线>/judge.jsonl
    裁定  python3 tools/newfp.py data/runs/<名字>/judge.jsonl [code]   # 新FP 裁进 gt-补丁
    分析  python3 tools/err.py data/runs/<名字>/judge.jsonl <code> fn --full
    优化  只改 judge/rubric.py 的判据文本，一次一条，改完记指纹

一次只动一条判据。同时动两条，抖动 ±6 分会把因果关系盖掉。

**定向改动看逐判据，不看总分。**改了哪条，就看那条的 FN/FP 有没有按预期动、
别的判据有没有被波及。总分会被新FP 稀释，也会被连带效应放大或抵消。

**`--group one` 下改动没有作用域。**14 条判据共享一个 prompt，改一条的措辞会波及
别的条 —— 好的方向（`neg_2_1` 写清楚后 `neg_1_1` 召回跟着涨了 10 个点）和坏的方向都有。
最危险的是改「什么算出处 / 什么算依据」这类话：写进主题 hint 或写进某条判据的 desc，
加了「判这一条时」的限定也一样，`neg_2_2` 两次都被打崩（漏判 7→21、7→25）。
这类改动要先 `--group theme` 把判据拆开判，否则别碰。
